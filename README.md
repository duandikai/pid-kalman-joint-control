# Reproducible PID and Kalman filter joint simulation

This repository contains a simulation of encoder-angle and gyroscope-rate
feedback for a single robotic joint. `main.m` runs the controller comparisons,
step tests, and parameter/noise sensitivity cases, and saves their numerical
outputs, figures, configuration, and calculated statistics.

**Status:** this version reconstructs the methods described in
`Manuscript_1103.docx` using the original public script as the plant-model
reference. It is not the recovered original code for that manuscript. The
recomputed results do not all match its reported numbers. Read
`MANUSCRIPT_AUDIT.md` before using this package in a journal submission.
No parameter or random seed was tuned to match the manuscript's results.

## Run the complete simulation

1. Download the complete repository, including `data/noise_standard.csv`.
2. Open MATLAB and select this folder as the current folder.
3. Type `main` in the Command Window.

```matlab
main
```

The implementation uses base MATLAB functions; Statistics and Machine Learning
Toolbox, Control System Toolbox, Simulink, MuJoCo and Webots are not required.
MATLAB R2018b or newer is the intended environment. The supplied reference
results were executed and checked using GNU Octave 6.4.0 on Linux; execution
under MATLAB itself has not been verified in this revision.

For numerical output without plotting, or on a machine without a graphics
backend:

```matlab
results = main('my_results', false);
```

In GNU Octave, from the repository folder:

```sh
octave --no-gui --quiet --eval "main('results', false);"
```

Octave needs a working graphics toolkit, such as gnuplot, to export the PNG
figures when the second argument is `true`. MATLAB uses its own plotting
system. Plot appearance can differ between programs; the CSV data are the
authoritative numerical output.

## Data availability and output files

There are no empirical, participant, or third-party research data. All
trajectories, sensor measurements, and statistical outputs are generated by
numerical simulation. All model constants and settings are defined in the
`configuration` function inside `main.m`; there are no private model files or
unavailable inputs.

Run `main` to generate the complete reference run in `results/`. The GitHub
repository includes the source, exact input noise, documentation and small
summary files; full time-series outputs are generated and saved by the script.
The local delivery additionally includes a precomputed `reference_results.zip`,
which extracts to `results/` and can be supplied as Supporting Information
after the manuscript is reconciled. Generated outputs include:

| Output | Contents |
|---|---|
| `results/simulation_results.mat` | Complete configuration, noise, all 18 simulated trajectories, state/covariance/gain histories, metrics and manuscript comparison |
| `results/data/tracking_encoder.csv` | Encoder-only PID sinusoidal run |
| `results/data/tracking_lpf.csv` | 10-Hz LPF-PID sinusoidal run |
| `results/data/tracking_kf.csv` | Kalman-filter PID sinusoidal run |
| `results/data/step_*.csv` | Three independent 30-degree step tests |
| `results/data/robustness_*.csv` | Twelve noise/inertia/damping cases and their configuration table |
| `results/data/*_metrics.csv` | Metrics recalculable from each corresponding trajectory |
| `results/data/table2_controller_comparison.csv` | Recomputed controller comparison |
| `results/data/table3_robustness.csv` | Recomputed sensitivity comparison |
| `results/data/configuration.csv` | Every scalar and matrix entry in the model configuration |
| `results/data/phase_*.csv` | Phase differences and fitted sinusoidal coefficients |
| `results/data/nominal_*.csv` | Nominal polynomial and its poles |
| `results/data/estimator_eigenvalues.csv` | Eigenvalues of the steady estimator error update |

CSV headers include units. Each trajectory has 5001 samples, from 0 to 5 s,
with a 0.001 s sample interval. Values are saved with 17 significant digits,
before rounding for presentation. `NaN` in a sinusoidal-run settling or
overshoot field means that the step-only metric is not applicable. In a step
run, `NaN` settling time means that the response has not settled within the
5 s observation horizon.

The `summary/` directory provides the small metric and audit files without
requiring the simulation to be run first. `DATA_DICTIONARY.md`
maps each manuscript figure/table to the numerical columns used to generate it.

## Exact noise realization and reproducibility

`data/noise_standard.csv` is a deposited simulation input, generated once using
seed 42 in GNU Octave 6.4.0. See `data/PROVENANCE.md` for the exact command,
ordering, and SHA-256. The complete repository includes this file. The script
loads the same realization for every controller, reference, and sensitivity
case; only the specified noise standard deviation changes.

This avoids relying on identical `randn` implementations in different software
environments. If the noise file is absent, `main.m` can still run: it generates
a realization from seed 42 and saves it with the outputs. That fallback may
produce different numbers in another program, and is not an exact reproduction
of the deposited run. Do not remove the bundled noise file for reproduction.

## Model and analysis definitions

The original DC-motor algebraic current model, saturation, Coulomb-friction
deadband, gravity, disturbance, and semi-implicit Euler integration are
retained. Joint inertia is 0.5 kg m^2 and damping is 0.2 N m s/rad. The applied
voltage and current are clipped to +/-24 V and +/-10 A. Unsaturated voltage
commands are exported separately and must not be confused with applied voltage.

PID gains are Kp=25, Ki=20 and Kd=5, as specified in the revised manuscript.
The positional PID differentiates the error and accumulates its integral; no
anti-windup or method-specific retuning is added. The control at sample k uses
the current reference and the feedback estimate at k-1. Sensors measure the
updated plant state at k. The KF performs its prediction/update at k, for use
by the next control step. The exported KF estimate is the posterior estimate
at k, not a separately shifted estimate.

The encoder measures angle with standard deviation 0.2 deg and the gyro
measures angular velocity with standard deviation 0.5 deg/s. H=I2,
Q=diag(5e-7,1e-4), and R=diag([(0.2*pi/180)^2,(0.5*pi/180)^2]). The KF keeps
the nominal A and B in every sensitivity run. Its covariance uses the Joseph
update. The LPF is a first-order backward-Euler filter with
alpha=dt/(1/(2*pi*10)+dt), initialized at zero.

Tracking errors compare the reference against the simulated **true** state;
estimation errors compare a sensor/estimate against that same true state.
The primary RMSE, maximum error and RMS metrics use 1 <= t <= 5 s inclusive.
Full-record estimation RMSEs are also exported because the manuscript does
not unambiguously specify that estimation window. A 30-degree step's settling
time is the first sample after the final violation of the +/-0.6-degree band,
through the end of the record. Overshoot uses the entire step record.

Phase is obtained by least-squares fitting sin(2*pi*t), cos(2*pi*t) and an
intercept over 1–5 s. The KF and offline LPF are compared against the same
true angle trajectory from the KF-PID run. The offline LPF does not change
that trajectory. This phase procedure is explicit here but was not specified
in enough detail in the manuscript to recover its original phase numbers.

The 12 robustness cases vary noise standard deviation by 0.5, 1, 2 and 5;
plant inertia by 0.5, 0.8, 1.2 and 1.5; or plant damping by those four factors.
The assumed KF noise covariance and nominal model are held fixed. No Monte
Carlo inference, confidence intervals or significance tests are claimed from
this one common noise realization.

Nominal continuous poles include linearized gravity about theta=0, but omit
Coulomb friction, saturation, disturbances, discrete sampling and estimator
dynamics. They are not a proof of nonlinear closed-loop stability.

## Verification and manuscript status

The optional independent checker requires Python 3 and NumPy:

```sh
python verify_results.py results
```

It checks the 18 trajectories against physical identities, common sensor
noise, actuator limits, covariance positivity, every exported scalar metric,
Tables 2/3, phase fitting and manuscript audit flags. Repeated execution from
the bundled noise produced byte-identical copies of all 47 CSV output files
in the tested environment. See `VERIFICATION.md`.

Passing these checks verifies consistency of this computation. It does not
establish agreement with all numbers in the supplied manuscript. Only 22 of
the 60 audited numerical claims match its stated rounding. The differences
must be resolved by the authors before the response letter can state that all
manuscript results are reproduced. A public repository URL alone does not
resolve that discrepancy.
